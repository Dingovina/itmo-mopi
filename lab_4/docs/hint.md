## 1. Цель и постановка задачи

**Цель лабораторной:** синтезировать изображение 3D-сцены с **глобальным освещением** методом **трассировки путей** (path tracing).

**Идея path tracing:** яркость пикселя — это результат многих случайных «путей» света:

```
Камера → поверхность → … → источник света (или небо)
```

Мы трассируем луч **от камеры назад** (backward ray tracing). Для каждого пикселя генерируем `spp` случайных путей, усредняем вклад — получаем оценку **математического ожидания** яркости (метод Монте-Карло).

**Отличие от классического ray tracing:** в ray tracing отскоки часто детерминированы (зеркало всегда зеркально, диффуз — по закону). В path tracing на каждом отскоке **случайный выбор** направления + **взвешивание** (importance sampling), чтобы оценка была **несмещённой** и сходилась к физически правдоподобному результату.

## 3. Общая схема программы

```
main()
  ├─ parse CLI (getopt_long)
  ├─ load_scene()          — JSON → Scene
  ├─ build_lights()        — CDF источников
  ├─ setup_camera()        — базис камеры
  ├─ render_image()        — Монте-Карло по пикселям
  │    └─ trace_path()     — один случайный путь
  ├─ postprocess()         — нормировка, gamma
  └─ write_ppm()           — файл P3
```

**Ключевые структуры (`main.c`):**

- `Material` — `diffuse`, `mirror`, `emission` (RGB).
- `Triangle` — вершины, индекс материала, нормаль `n`, площадь `area`.
- `Scene` — материалы, треугольники, `LightSampler`, `RenderCfg`, `CameraCfg`.
- В `trace_path`: накопитель `L` (яркость в камеру), `beta` (вес пути / throughput).

## 4. Загрузка сцены

**Функции:** `read_file` → `cJSON_Parse` → `load_scene`, затем `triangle_make`, `clamp_material`.

### 4.1. Площадь и нормаль треугольника

Рёбра:

\[
\mathbf{e}_1 = \mathbf{v}_1 - \mathbf{v}_0,\quad \mathbf{e}_2 = \mathbf{v}_2 - \mathbf{v}_0
\]

Нормаль (не нормированная):

\[
\mathbf{n}_{raw} = \mathbf{e}_1 \times \mathbf{e}_2
\]

Площадь:

\[
A = \frac{1}{2}\|\mathbf{n}_{raw}\|
\]

Единичная нормаль (в коде `triangle_make`):

\[
\mathbf{n} = \frac{\mathbf{n}_{raw}}{\|\mathbf{n}_{raw}\|}
\]

### 4.2. Физичность материала (`clamp_material`)

Для каждого канала \(c \in \{R,G,B\}\):

\[
k_{d,c} + k_{s,c} \le 1
\]

Если \(k_d + k_s > 1\), оба масштабируются:

\[
k = \frac{1}{k_d + k_s},\quad k_d' = k\,k_d,\quad k_s' = k\,k_s
\]

**Зачем:** энергия не «создаётся» при отражении; это требование задания.

### 4.3. Значения по умолчанию

Если в JSON не задано: `width/height=500`, `spp=4`, `max_depth=8`, `gamma=2.2`, `normalize="max"`.

## 5. Геометрия: треугольники и пересечения

### 5.1. Луч

\[
\mathbf{x}(t) = \mathbf{o} + t\,\mathbf{d},\quad t > 0
\]

`Ray`: `o` — начало, `d` — направление (в коде обычно **нормировано** для камеры и отскоков).

### 5.2. Möller–Trumbore (`intersect_triangle`)

Классический алгоритм пересечения луча с треугольником. Обозначения как в коде:

\[
\mathbf{p} = \mathbf{d} \times \mathbf{e}_2,\quad \det = \mathbf{e}_1 \cdot \mathbf{p}
\]

Если \(|\det| < 10^{-9}\) — луч параллелен плоскости, пересечения нет.

\[
\mathbf{tvec} = \mathbf{o} - \mathbf{v}_0,\quad u = \frac{\mathbf{tvec}\cdot\mathbf{p}}{\det}
\]

Условие попадания в треугольник: \(u \ge 0,\; v \ge 0,\; u+v \le 1\).

\[
\mathbf{q} = \mathbf{tvec} \times \mathbf{e}_1,\quad v = \frac{\mathbf{d}\cdot\mathbf{q}}{\det},\quad t = \frac{\mathbf{e}_2\cdot\mathbf{q}}{\det}
\]

Условие видимости впереди: \(t > \varepsilon\) (`EPS = 1e-6`).

### 5.3. Ближайшее пересечение (`intersect_scene`)

Линейный перебор всех треугольников, выбирается минимальное \(t\).

Точка попадания:

\[
\mathbf{x} = \mathbf{o} + t\,\mathbf{d}
\]

**Ориентация нормали:** если \(\mathbf{n}\cdot\mathbf{d} > 0\), нормаль разворачивается: \(\mathbf{n} \leftarrow -\mathbf{n}\), чтобы смотреть «против луча» (внешняя сторона для луча из камеры).

### 5.4. Теневой луч (`is_occluded`)

Для расстояния до источника `max_dist`: если есть пересечение с \(t < \texttt{max\_dist} - 10^{-4}\), точка в тени.

Теневой луч стартует со смещением:

\[
\mathbf{o}_{shadow} = \mathbf{x} + \varepsilon\,\mathbf{n},\quad \varepsilon = 10^{-4}
\]

(защита от self-intersection).

## 6. Модель материала

Материал задаётся тремя RGB-векторами:

| Поле | Смысл | Физика |
|------|--------|--------|
| `diffuse` | \( \mathbf{k}_d \) | Lambert: рассеянное отражение |
| `mirror` | \( \mathbf{k}_s \) | Идеальное зеркало (δ-BRDF), цвет отражения |
| `emission` | \( \mathbf{L}_e \) | Самосвечение (источник) |

### 6.1. Lambert BRDF

Для диффузной поверхности:

\[
f_r(\omega_i \leftrightarrow \omega_o) = \frac{\mathbf{k}_d}{\pi}
\]

(в коде — покомпонентно: `f = diffuse / PI`).

### 6.2. Идеальное зеркало

Отражение направления луча \(\mathbf{d}\) относительно нормали \(\mathbf{n}\) (`v3_reflect`):

\[
\mathbf{d}_{refl} = \mathbf{d} - 2(\mathbf{d}\cdot\mathbf{n})\,\mathbf{n}
\]

Затем нормализация: `v3_norm`.

**Важно:** при зеркальном отскоке вес пути умножается на \(\mathbf{k}_s\) (цветное зеркало — «красный металл» и т.д.).

### 6.3. Комбинированный материал

Реальная поверхность — смесь: с вероятностью отражаем диффузно, иначе зеркально (см. §11). Это **не** физически строгая microfacet-модель (Cook-Torrance), но соответствует заданию.

## 7. Источники света и CDF

### 7.1. Кто считается источником

В `build_lights` перебираются треугольники, у которых `emission` имеет хотя бы один канал \(> 0\).

### 7.2. Мощность источника

Упрощённая скалярная мощность (как в коде):

\[
P_i = A_i \cdot (L_{e,i}^R + L_{e,i}^G + L_{e,i}^B)
\]

где \(A_i\) — площадь треугольника-источника.

**Замечание для защиты:** это эвристика для importance sampling, не строгая фотометрическая мощность в ваттах; главное — пропорции между источниками.

### 7.3. CDF (кумулятивное распределение)

Строится массив `cdf[k] = \sum_{j=0}^{k} P_j`, `total = cdf[count-1]`.

**Выбор источника** (`lights_sample`): \( \xi \sim U(0, \texttt{total}) \), бинарный поиск по `cdf`.

Вероятность выбора \(i\)-го источника:

\[
p_{sel,i} = \frac{P_i}{\sum_j P_j}
\]

В коде для выбранного `lo`:

\[
p_{sel} = \frac{\texttt{cdf[lo]} - \texttt{cdf[lo-1]}}{\texttt{total}}
\]

(для `lo=0` предыдущий CDF = 0).

### 7.4. Случайная точка на треугольнике (`sample_point_on_triangle`)

Равномерная выборка по площади (барицентрические координаты):

\[
\sqrt{\xi_1} = su,\quad a = 1-su,\quad b = su(1-\xi_2),\quad c = su\cdot\xi_2
\]

\[
\mathbf{x}_L = a\,\mathbf{v}_0 + b\,\mathbf{v}_1 + c\,\mathbf{v}_2
\]

PDF по площади на источнике:

\[
p_A(\mathbf{x}_L) = \frac{1}{A_{light}}
\]

## 8. Камера и первичный луч

### 8.1. Базис камеры (`setup_camera`)

Позиция: \(\mathbf{C} =\) `pos`.

Направление взгляда:

\[
\mathbf{f} = \mathrm{normalize}(\mathbf{look\_at} - \mathbf{C})
\]

Правый вектор:

\[
\mathbf{r} = \mathrm{normalize}(\mathbf{f} \times \mathbf{up})
\]

Вектор «вверх» в кадре:

\[
\mathbf{u}_{cam} = \mathrm{normalize}(\mathbf{r} \times \mathbf{f})
\]

Полуширина кадра на фокальном расстоянии 1 (pinhole):

\[
\texttt{scale} = \tan\left(\frac{\texttt{fov\_deg}}{2} \cdot \frac{\pi}{180}\right)
\]

Соотношение сторон:

\[
\texttt{aspect} = \frac{w}{h}
\]

### 8.2. Первичный луч (`make_camera_ray`)

Нормированные координаты пикселя \((u, v) \in [0,1]^2\) (с jitter — см. §13):

\[
p_x = (2u - 1)\cdot \texttt{aspect}\cdot \texttt{scale}
\]
\[
p_y = (1 - 2v)\cdot \texttt{scale}
\]

Направление:

\[
\mathbf{d} = \mathrm{normalize}(p_x\,\mathbf{r} + p_y\,\mathbf{u}_{cam} + \mathbf{f})
\]

Луч: \(\mathbf{o} = \mathbf{C}\), \(\mathbf{d}\) как выше.

**Точечная камера:** все первичные лучи выходят из одной точки \(\mathbf{C}\).

## 9. Монте-Карло и трассировка пути

### 9.1. Что оцениваем

Для пикселя хотим оценить **спектральную яркость** (RGB) \( \mathbf{L}_{pixel} \), которую даёт интеграл по всем путям:

\[
\mathbf{L}_{pixel} \approx \frac{1}{N}\sum_{k=1}^{N} \mathbf{L}_{path}^{(k)},\quad N = \texttt{spp}
\]

Каждый `trace_path` — одна реализация случайного пути.

### 9.2. Переменные в `trace_path`

| Переменная | Смысл |
|------------|--------|
| `L` | накопленная яркость, дошедшая до камеры по текущему пути |
| `beta` | throughput (произведение BRDF / PDF / вероятностей выбора) |
| `depth` | номер отскока (0 … `max_depth-1`) |

Изначально: \(\mathbf{L} = (0,0,0)\), \(\boldsymbol{\beta} = (1,1,1)\).

### 9.3. Цикл одного отскока

На каждой итерации:

1. `intersect_scene` — найти поверхность.
2. Если промах — выход (чёрный фон, вклад 0).
3. Если `emission > 0` — добавить \(\boldsymbol{\beta} \odot \mathbf{L}_e\), **конец пути** (попали на лампу).
4. Иначе — **NEE** (прямой свет), если есть диффуз.
5. Выбор диффуз / зеркало, обновление \(\boldsymbol{\beta}\) и нового луча.
6. Русская рулетка (с `depth >= 3`).

\(\odot\) — покомпонентное умножение (`v3_mulv`).

### 9.4. Попадание на источник

\[
\mathbf{L} \mathrel{+}= \boldsymbol{\beta} \odot \mathbf{L}_e
\]

Путь обрывается — дальше луч не трассируется.

## 10. Прямое освещение (NEE)

**NEE** = Next Event Estimation — явно соединяем точку на поверхности с источником одним лучом. Это резко ускоряет сходимость (особенно для малых источников).

**Условие в коде:** только если `diffuse > 0` (чистое зеркало NEE не получает на этом отскоке).

### 10.1. Шаги (функция внутри `trace_path`)

1. `lights_sample` → треугольник-источник, \(p_{sel}\).
2. `sample_point_on_triangle` → точка \(\mathbf{x}_L\) на источнике.
3. Направление к источнику:

\[
\mathbf{w}_i = \frac{\mathbf{x}_L - \mathbf{x}}{\|\mathbf{x}_L - \mathbf{x}\|}
\]

4. Косинусы (Lambert на приёмнике и на источнике):

\[
\cos_x = \max(0,\; \mathbf{n}\cdot\mathbf{w}_i)
\]
\[
\cos_l = \max(0,\; \mathbf{n}_L\cdot(-\mathbf{w}_i))
\]

5. **Shadow ray:** если `is_occluded` — вклад 0 (тень).

6. Геометрический фактор (универсальный для точечной пары):

\[
G = \frac{\cos_x \cdot \cos_l}{\|\mathbf{x}_L - \mathbf{x}\|^2}
\]

7. BRDF Ламберта: \(\mathbf{f} = \mathbf{k}_d / \pi\).

8. PDF всей выборки (источник × точка на площади):

\[
p_{light} = p_{sel} \cdot \frac{1}{A_{light}}
\]

9. **Вклад прямого света** (несмещённая оценка Монте-Карло):

\[
\mathbf{L} \mathrel{+}= \boldsymbol{\beta} \odot \mathbf{L}_e \odot \mathbf{f} \odot \frac{G}{p_{light}}
\]

(в коде всё через `v3_mulv` и скалярное деление на `pdf_light`).

**Соответствие заданию:** один случайный луч к случайному источнику, точка на треугольнике равномерна, яркость по поверхности источника постоянна.

## 11. Диффузный и зеркальный отскок

На поверхности выбирается **одно** событие (задание).

### 11.1. Вероятности (упрощение по среднему RGB)

\[
\bar{d} = \frac{k_d^R + k_d^G + k_d^B}{3},\quad
\bar{s} = \frac{k_s^R + k_s^G + k_s^B}{3}
\]

\[
p_{diff} = \frac{\bar{d}}{\bar{d} + \bar{s}}
\]

Если \(\bar{d} + \bar{s} = 0\) — путь обрывается.

### 11.2. Диффузный отскок

С вероятностью \(p_{diff}\):

**Выборка направления** — косинусная полусфера (`sample_cosine_hemisphere`):

В локальной системе с осью \(\mathbf{n}\): \(\xi_1,\xi_2 \sim U(0,1)\):

\[
\phi = 2\pi\xi_1,\quad r = \sqrt{\xi_2}
\]
\[
x = r\cos\phi,\quad y = r\sin\phi,\quad z = \sqrt{1-r^2}
\]

Локальное направление \((x,y,z)\) переводится в мировые координаты через базис `orthonormal_basis` (\(\mathbf{t}, \mathbf{b}, \mathbf{n}\)).

**PDF** косинусной выборки: \(p_\omega(\omega) = \cos\theta / \pi\) (используется неявно через деление на \(p_{diff}\) и умножение на \(k_d\)).

**Обновление throughput:**

\[
\boldsymbol{\beta} \mathrel{*}= \frac{\mathbf{k}_d}{p_{diff}}
\]

(\(\mathrel{*}=\) покомпонентно).

Новый луч: \(\mathbf{o} = \mathbf{x} + \varepsilon\mathbf{n}\), \(\mathbf{d} = \omega_{new}\).

### 11.3. Зеркальный отскок

С вероятностью \(1 - p_{diff}\):

\[
\mathbf{d}_{new} = \mathrm{normalize}(\mathrm{reflect}(\mathbf{d}, \mathbf{n}))
\]

\[
p_m = 1 - p_{diff}
\]

\[
\boldsymbol{\beta} \mathrel{*}= \frac{\mathbf{k}_s}{p_m}
\]

Смещение начала луча: \(\mathbf{o} = \mathbf{x} + \varepsilon\mathbf{n}\).

**Глобальное освещение:** после диффузного отскока луч может попасть на другую поверхность, снова NEE + отскок — так появляются **цветные отражения на полу**, мягкие тени и т.д.

**Зеркало в кадре:** камера → зеркало → объект; объект должен иметь \(k_d > 0\) или emission, чтобы вклад дошёл (чистое зеркало само NEE не считает).

## 12. Русская рулетка

**Цель:** оборвать длинные пути без систематической ошибки (несмещённый estimator).

Срабатывает при `depth >= 3`:

\[
q = \mathrm{clamp}\big(\max(\beta_R,\beta_G,\beta_B),\; 0.05,\; 0.95\big)
\]

- С вероятностью \(q\) путь **продолжается**, \(\boldsymbol{\beta} \mathrel{/}= q\).
- Иначе `break`.

**Идея:** чем меньше вес пути, тем чаще обрываем, но деление на \(q\) компенсирует обрыв в среднем.

## 13. Цикл рендера и антиалиасинг

**Функция:** `render_image`.

Для каждого пикселя \((x,y)\), для \(s = 0 \ldots \texttt{spp}-1\):

**Jitter (стохастический антиалиасинг):**

\[
u = \frac{x + \xi_1}{w},\quad v = \frac{y + \xi_2}{h},\quad \xi \sim U(0,1)
\]

(`rng_next`).

**Усреднение:**

\[
\mathbf{C}(x,y) = \frac{1}{\texttt{spp}}\sum_{s} \mathbf{L}_{path}^{(s)}
\]

Буфер `img[]` хранит **HDR** (значения могут быть \(> 1\)).

**ГПСЧ:** xorshift64* в `rng_next` (детерминирован при фиксированном `--seed`).

## 14. Постобработка и PPM

**Функция:** `postprocess`.

### 14.1. Нормировка (`normalize: "max"`)

\[
I' = \frac{I}{\max\limits_{\text{pixels}} \big(\max(R,G,B)\big)}
\]

Ярчайший пиксель → 1.0; это **экспозиция**, не физика сцены.

### 14.2. Clamping

\[
I'' = \mathrm{clamp}(I',\, 0,\, 1)
\]

покомпонентно (`v3_clamp01`).

### 14.3. Гамма-коррекция (из задания)

\[
V_{corr} = V''^{1/\gamma}
\]

В коде: `inv_g = 1/gamma`, `pow(c, inv_g)` по каналам. Обычно \(\gamma = 2.2\).

**Зачем:** монитор нелинеен; без гаммы картинка темнее ожидаемого.

### 14.4. Запись PPM (`write_ppm`)

Формат **P3** (ASCII):

```
P3
width height
255
R G B R G B ...
```

Квантование:

\[
\text{byte} = \mathrm{round}(255 \cdot V_{corr})
\]

с отсечением в \([0,255]\).

## 16. Типичные вопросы на защите

### «Чем path tracing отличается от ray tracing?»

Ray tracing часто строит детерминированные цепочки (отражение, тень). Path tracing — **Монте-Карло**: случайные направления, усреднение по `spp`, оценка интеграла освещённости; естественно даёт **глобальное освещение** (межотражения).

### «Где у вас global illumination?»

В цепочке **диффузных** отскоков: свет от стен/пола попадает на объекты; в **зеркальных** — отражение сцены. Плюс NEE даёт прямой свет от area source.

### «Почему шум на картинке?»

Дисперсия Монте-Карло; убывает примерно как \(1/\sqrt{\texttt{spp}}\). Увеличить `spp` — меньше шума, дольше счёт.

### «Почему \(k_d + k_s \le 1\)?»

Энергетическая сохранность в упрощённой модели: доля отражённого света по каналу не превышает 100%.

### «Почему один луч прямого света?»

Требование задания; NEE с одной выборкой источника + точки — несмещённая оценка, но с шумом. Больше лучей NEE на отскок — можно добавить, в коде — один.

### «Как доказать корректность?»

1. Рост `spp` → шум падает, структура стабильна.  
2. `max_depth=1` vs `8` → появляются межотражения.  
3. Убрать emission / изменить цвета в JSON — предсказуемый эффект.  
4. Зеркало должно показывать объекты **перед** ним в направлении отражённого луча (геометрия).

### «Почему в зеркале не видно объект?»

Часто **геометрия**: отражённый луч не попадает на объект (угол, позиция). Реже — объект в тени, чистое зеркало без диффуза на отражённой цепочке. Проверять: положение камеры, зеркала и объекта по оси X (зеркало на правой стене).

### «Почему разные строки рендерятся с разной скоростью?»

Одинаковый код на пиксель, но **разная сложность пути**: центр кадра — больше геометрии, зеркала, отскоков; верх — часто промах или простая геометрия.

### «Какая сложность пересечений?»

\(O(N_{tri})\) на луч; для ~30 треугольников достаточно. Embree не используется — допустимо по заданию.

### «Что такое \(\beta\)?»

**Throughput** — накопленный вес пути; сколько «яркости источника» доходит до камеры с учётом BRDF и вероятностей выбора событий.

### «Почему делим на \(p_{diff}\) и \(p_m\)?»

Иначе оценка Монте-Карло будет **смещённой**: редкие события (зеркало) должны вносить вклад с весом \(1/p\).

## 17. Упрощения и ограничения кода

Честно назвать на защите:

1. **Нет преломления, нет subsurface, нет Cook-Torrance.**
2. **Перебор треугольников** вместо BVH/Embree.
3. **Вероятности диффуз/зеркало** — по среднему RGB, не по полной физике Fresnel.
4. **Мощность источника** — сумма RGB × площадь, не строгая радиометрия.
5. **Нормировка `max`** — произвольная экспозиция кадра.
6. **Только режим `normalize: "max"`** в коде (другие строки в JSON игнорируются).
7. **Русская рулетка** с фиксированными порогами 0.05 / 0.95.
8. **π = 3.1415926** в `#define PI` (мелкая погрешность).
9. **Зеркало** не получает NEE на своей поверхности (`diffuse = 0`); видимость объектов в зеркале — только через отражённый луч и последующие диффузные/emission поверхности.
10. **Нет MIS** (multiple importance sampling) между NEE и случайным отскоком.

## Краткая формульная шпаргалка «один пиксель»

```
для s = 1 … spp:
  u = (x + ξ1)/w,  v = (y + ξ2)/h
  луч (C, d(u,v))                           — §8
  L_path = 0, β = 1
  для depth = 0 … max_depth-1:
    пересечение → x, n, материал          — §5
    если emission: L += β·Le; стоп         — §9
    NEE: L += β·Le·(kd/π)·G / p_light      — §10
    с вер. p_diff: косинусный ω, β*=kd/p_diff   — §11
    иначе: reflect(d,n), β*=ks/(1-p_diff)
    русская рулетка с depth≥3               — §12
  C += L_path
C /= spp
C /= max(кадра); clamp; C^(1/γ); PPM         — §14
```
