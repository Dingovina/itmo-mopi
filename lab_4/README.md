# Лабораторная 4 — трассировка путей (минимальная реализация)

Эта папка содержит **минимальный** трассировщик путей (path tracing) для сцены из треугольников с:

- глобальным освещением (непрямой свет за счёт случайных отскоков луча),
- протяжёнными источниками света (area light) на треугольниках,
- материалами: **Ламберт (diffuse)** и **идеальное зеркало (mirror)**,
- антиалиасингом (джиттер внутри пикселя),
- нормировкой яркости, клиппингом, гамма-коррекцией и записью в **PPM**.

Код: [`main.py`](./main.py)  
Параметры сцены: [`scene.json`](./scene.json)

---

## Быстрый старт

Рендер “по заданию” (не меньше 500×500):

```bash
python3 lab_4/main.py --spp 50 --max-depth 8 --out lab_4/output.ppm
```

Быстрый тест (маленькое изображение, просто проверить что работает):

```bash
python3 lab_4/main.py --w 64 --h 64 --spp 2 --max-depth 4 --out lab_4/out_test.ppm
```

## Как формируется изображение (пошагово)

Ниже описан весь процесс “от пикселя до файла” и где он реализован в коде.

### 1) Считывание сцены и параметров

Сцена задаётся в [`scene.json`](./scene.json):

- `render`: параметры рендера (размер, число сэмплов и т.д.)
- `camera`: параметры камеры
- `materials`: список материалов
- `triangles`: список треугольников (геометрия)

Загрузка из JSON: функция `load_scene()` в [`main.py`](./main.py).  
Там же делается проверка “физичности” материала: **`diffuse + mirror <= 1` по компонентам RGB** (если больше — коэффициенты поджимаются).

### 2) Камера (pinhole) и первичные лучи

Камера точечная (pinhole): из точки `camera.pos` выпускаются лучи через воображаемый экран.

- построение базиса камеры и генератор лучей: `make_camera_rays()` в [`main.py`](./main.py)
- антиалиасинг: в цикле рендера берётся случайная точка **внутри пикселя**:
  - `u = (x + rand()) / width`
  - `v = (y + rand()) / height`
  - это находится в `main()` (цикл по пикселям)

Термины:
- **FOV** (`camera.fov_deg`) — угол обзора (ширина “объектива”).
- **Антиалиасинг** — сглаживание “ступенек” на границах объектов за счёт случайного сдвига луча внутри пикселя.

### 3) Пересечение луча со сценой (луч–треугольник)

Сцена — это список треугольников. Для каждого луча ищется ближайшее пересечение:

- пересечение луча с одним треугольником: `intersect_triangle()` (алгоритм **Möller–Trumbore**)
- перебор всех треугольников и выбор ближайшего: `intersect_scene()`

Это “минимальная планка”: без BVH/ускоряющих структур.

### 4) Источники света (area light)

Источники света задаются как **треугольники**, у материала которых `emission != 0`.

- сбор списка источников и построение распределения по мощности: `build_lights()`
- выбор источника по вероятности (importance sampling): `LightSampler.sample()`
- выбор случайной точки на треугольнике равномерно по площади: `sample_point_on_triangle()`

Термины:
- **Протяжённый источник** — не точка, а поверхность (треугольник), которая излучает свет.
- **Importance sampling** (выборка по значимости) — выбираем источник чаще, если он “мощнее” (у нас мощность \(\sim area * sum(emission)\)).

### 5) Трассировка путей (Path Tracing)

Основная функция: `trace_path()` в [`main.py`](./main.py).

Она делает цикл по “отскокам” луча:

1) Находим пересечение с сценой (`intersect_scene`).
2) Если попали в источник света (`material.emission > 0`) — добавляем излучение и заканчиваем путь.
3) Считаем **прямое освещение** (одна случайная выборка источника + один теневой луч).
4) Выбираем событие на поверхности: **диффузия или зеркало**.
5) Генерируем новое направление луча и продолжаем.
6) После нескольких отскоков включаем **русскую рулетку** (вероятностно обрываем путь, чтобы экономить время).

Термины:
- **Путь (path)** — последовательность “камера → поверхность → поверхность → ...”.
- **Глобальное освещение** — учитывается за счёт непрямых отскоков (свет может прийти не напрямую от лампы, а после отражений).
- **Русская рулетка** — способ обрывать “длинные” лучи без сильного смещения результата:
  - чем меньше энергия луча, тем вероятнее обрыв.

### 6) Прямое освещение (теневой луч)

Внутри `trace_path()` есть блок “прямой свет (1 выбор)”:

- выбираем световой треугольник по мощности (`lights.sample`)
- выбираем случайную точку на нём (`sample_point_on_triangle`)
- строим **теневой луч** (shadow ray) к этой точке и проверяем видимость (`intersect_scene`)

Если точка видима — добавляем вклад **по базовой формуле Монте‑Карло**:

- `pdf_light = p_select * (1 / area_light)`
- геометрический множитель: `G = (cos_x * cos_l) / dist^2`
- BRDF Ламберта: `f = diffuse / pi`
- вклад добавляется в `L`

Термины:
- **Теневой луч** — луч “к источнику”, проверяет, закрывает ли кто-то свет (есть ли тень).
- **PDF** (probability density function) — плотность вероятности выбранного сэмпла. Нужна, чтобы оценка была корректной (в среднем).
- **BRDF** — модель отражения поверхности. Для Ламберта это константа `diffuse/pi`.

### 7) Материалы: diffuse и mirror + выбор события

Материал задаётся двумя цветными коэффициентами:

- `diffuse` — доля диффузного отражения (матовая поверхность)
- `mirror` — доля зеркального отражения (идеальное зеркало)

В `trace_path()` выбирается одно событие (diffuse или mirror) по “силе”:

- `p_diff = avg(diffuse) / (avg(diffuse) + avg(mirror))`
- иначе событие “зеркало”

Для диффузии:
- направление выбирается по косинусному закону: `sample_cosine_hemisphere()`

Для зеркала:
- направление считается функцией `reflect()`

Почему это нужно:
- По заданию на одной поверхности могут быть оба свойства, но на каждом отскоке мы выбираем **одно** событие.
- “Выборка по значимости” помогает чаще выбирать более сильное свойство.

### 8) Остановка трассировки

Два ограничения:

- `max_depth` — максимальное число отскоков (параметр рендера)
- русская рулетка после нескольких отскоков — в `trace_path()`

Это соответствует требованию задания “ограничить продолжительность расчёта”.

### 9) Постобработка и запись в PPM

Сначала картинка копится в “абсолютных яркостях” (float RGB).  
Потом делаем:

1) **Нормировка** (`normalize = "max"`): делим всю картинку на максимальную яркость кадра  
   Реализовано в `postprocess()`.
2) **Клиппинг** (всё что > 1 → 1): `Vec3.clamp01()`
3) **Гамма-коррекция**: \(V_{corr} = V^{1/gamma}\), `gamma=2.2`  
   Реализовано в `postprocess()`.
4) Перевод в 0..255 и запись файла PPM:
   - `write_ppm_p3()` пишет **P3 (ASCII)** — самый простой формат.

## Параметры: что означает и где задаётся

### Параметры рендера (`render` в `scene.json`)

- **`width`, `height`**: размер изображения (по заданию: **>= 500×500**, **<= 1000×1000**).  
  Используются в `main()` при выборе `w`, `h`.
- **`spp`**: samples per pixel — сколько случайных лучей на пиксель. Больше `spp` → меньше шум, больше время.  
  Используется в цикле по пикселям в `main()`.
- **`max_depth`**: максимум отскоков луча. Больше → лучше непрямой свет, но дольше.  
  Передаётся в `trace_path()`.
- **`gamma`**: параметр гамма-коррекции (обычно 2.2).  
  Используется в `postprocess()`.
- **`normalize`**: способ нормировки. Сейчас поддерживается `"max"`.  
  Используется в `postprocess()`.

### Параметры камеры (`camera` в `scene.json`)

- **`pos`**: позиция камеры.
- **`look_at`**: точка, куда камера смотрит.
- **`up`**: вектор “вверх” (обычно `[0,1,0]`).
- **`fov_deg`**: угол обзора.

Все они читаются в `main()` и идут в `make_camera_rays()`.

### Материалы (`materials` в `scene.json`)

Для каждого материала:

- **`diffuse`**: диффузное отражение (Ламберт), RGB 0..1.
- **`mirror`**: зеркальное отражение, RGB 0..1.
- **`emission`**: излучение (если не ноль — это источник света).

Чтение и проверка физичности — в `load_scene()`.

### Геометрия (`triangles` в `scene.json`)

Каждый треугольник:

- **`mat`**: индекс материала из массива `materials`.
- **`v0`, `v1`, `v2`**: координаты вершин.

Из них строится структура `Triangle` (нормаль и площадь считаются в `triangle_make()`).

### Параметры командной строки (CLI)

См. `main()`:

- `--scene`: путь к `scene.json` (по умолчанию `lab_4/scene.json`)
- `--out`: куда сохранить PPM (по умолчанию `lab_4/output.ppm`)
- `--w`, `--h`: переопределить размер (0 = взять из `scene.json`)
- `--spp`: переопределить `spp`
- `--max-depth`: переопределить `max_depth`
- `--seed`: seed генератора случайных чисел (удобно для сравнения результатов)

## Почему картинка “шумная”

Это нормально для path tracing при маленьком `spp`.  
Чтобы было “чище”:

- поднимай `spp` (например 50–200),
- можно чуть уменьшить зеркальность или сделать источники света больше/ярче (в `scene.json`).

---

## Что менять на защите (быстро показать, что всё работает)

Ниже — самые “наглядные” параметры, которые можно менять прямо во время защиты. Идея: менять 1 параметр → перерендерить → показать, что картинка меняется ожидаемо.

### 1) Качество/время рендера: `spp`

Где задаётся:
- в `scene.json`: `render.spp`
- или в CLI: `--spp` (переопределяет JSON)

Что будет видно:
- `spp` больше → **меньше шум** (картинка “чище”), но **дольше**.

Рекомендации:
- “быстро показать”: `--spp 10` (шумно, но быстро)
- “нормально выглядит”: `--spp 50`
- “уже довольно чисто”: `--spp 100..200`

Пример:

```bash
python3 lab_4/main.py --spp 10  --out lab_4/defense_spp10.ppm
python3 lab_4/main.py --spp 100 --out lab_4/defense_spp100.ppm
```

### 2) Глобальное освещение: `max_depth`

Где задаётся:
- в `scene.json`: `render.max_depth`
- или в CLI: `--max-depth`

Что будет видно:
- маленький `max_depth` (например 1–2) → почти только прямой свет, “плоско”
- больше `max_depth` (например 6–10) → появляются **подсветка в тенях** и “переотражения” (непрямой свет)

Пример:

```bash
python3 lab_4/main.py --spp 50 --max-depth 2 --out lab_4/defense_d2.ppm
python3 lab_4/main.py --spp 50 --max-depth 8 --out lab_4/defense_d8.ppm
```

### 3) Яркость/цвет источника: `materials[].emission`

Где задаётся:
- в `scene.json`: у материала света, например `"name": "light"` → поле `emission: [R,G,B]`

Что будет видно:
- больше `emission` → картинка ярче
- разные RGB → свет становится цветным

Пример:
- было: `"emission": [12, 12, 12]` (белый свет)
- сделать: `"emission": [12, 8, 8]` (тёплый свет)

### 4) Материал объекта: `materials[].diffuse` и `materials[].mirror`

Где задаётся:
- в `scene.json`: список `materials`, затем треугольник выбирает материал по `triangles[].mat`

Что будет видно:
- увеличить `diffuse` → поверхность светлее/матовее
- увеличить `mirror` → появляются зеркальные отражения (и чаще заметны “искры”/шум при малом `spp`)

Важно:
- в коде есть проверка физичности: если `diffuse + mirror > 1`, коэффициенты поджимаются (см. `load_scene()` в `main.py`).
